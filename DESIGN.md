# Recall: temporal evidence before confident prose

## How it works
A dependency-free Node HTTP server serves a small browser client and a session-scoped chat API. For each turn, deterministic retrieval selects timestamped user messages, adjacent assistant baselines, lexical entity matches, and recent context across that browser's conversations. Browser IANA timezone resolves calendar references; UTC timestamps remain the canonical record. Gemini receives the current question plus selected historical evidence, with Google Search as its only external tool. The server converts actual grounding metadata to source links and exact-segment citation markers. It atomically persists the successful user/assistant pair and exposes an evidence trail: memory IDs, interpreted day, search metadata, model, latency, usage, and finish reason. NDJSON streams real stage progress, followed by the completed answer, not fabricated token progress.

## Why this design
The challenge is temporal continuity: “those five CRMs” must mean the original five, and “changed since Tuesday” needs a dated baseline, not merely today's price. Historical dialogue proves what was said; current web evidence supports what is true now; neither alone proves when something changed. The policy keeps these categories distinct and requests clarification when the shortlist is missing. One model generation normally avoids planner latency and one API key covers both research and generation. Deterministic retrieval is inspectable and testable without a model. Citation insertion uses provider support text instead of guessed UTF-16 offsets. A plain-text DOM renderer prevents model-output HTML injection. The UI presents unsupported grounding honestly rather than turning every answer green.

## Trade-offs and rejected alternatives
I rejected a multi-agent planner/researcher/critic chain: it adds latency and opaque failure modes before establishing a measured quality gain. I rejected embeddings and a vector database at this scale: extra keys/infrastructure obscure date/entity exactness, though lexical retrieval can miss synonyms. I rejected context-dumping all history: it grows costs, distracts the model, and exposes unnecessary messages. I rejected a custom search scraper: Gemini grounding provides the only permitted external tool without a second credential. I rejected response caching for current pricing because stale “unchanged” answers are especially dangerous. I kept persistence behind a Store boundary but deliberately used serialized atomic JSON replacement to keep `npm install && npm run dev` portable and dependency-free; the cost is single-process operation and whole-file writes. This is not a substitute for a production database. No claim is made that prompt-injection defenses or model accuracy are proven.

## What another week buys
First run a dated-history evaluation set and review every cited claim, recording correctness, honest uncertainty, and p50/p95 latency against a stateless baseline. Add a clarifying retrieval pass only where measured failures justify the extra call. Then move to authenticated users and Postgres transactions, add retention/backups and global quotas, and improve date ranges, multiple references, semantic recall, long-message budgeting, cancellation/idempotency, and truncation handling. Verify Search-suggestion compliance and browser rendering with a real key. Current verification covers offline logic and HTTP behavior, not real Gemini accuracy. The architecture's goal is an agent that admits an unknown baseline, not an agent that confidently manufactures one.
